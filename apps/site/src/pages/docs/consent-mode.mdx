Consent Mode is how Google's tags (GA4, Google Ads, Floodlight, and the third-party tags in GTM that support it) know what they may do. easy-cookie handles it in two steps: a synchronous **default** in `<head>`, before GTM, and an **update** after every choice.

Turn it on in the config:

```ts
googleConsentMode: { enabled: true },
```

## Categories and signals

| Category | Signals granted when accepted |
|---|---|
| `necessary` | `security_storage` (always granted) |
| `functionality` | `functionality_storage` |
| `experience` | `personalization_storage` |
| `measurement` | `analytics_storage` |
| `marketing` | `ad_storage`, `ad_user_data`, `ad_personalization` |

Category ids are yours to choose. The five above only come with default titles and signals; any other id gets its signals from `gcm`. A category called `analytics` works exactly like `measurement` with:

```ts
categories: {
  necessary: { readOnly: true },
  analytics: { title: { it: 'Statistiche', en: 'Analytics' }, gcm: ['analytics_storage'] },
},
```

`gcm` also overrides the defaults of a known id. A signal is granted when at least one accepted category includes it. The four core v2 signals (`ad_storage`, `ad_user_data`, `ad_personalization`, `analytics_storage`) are always declared, denied unless granted, so tags never see an undefined state.

Once at least one service is declared, an optional category with no services is left out of Consent Mode along with the banner, and its signals are never granted (see [Categories follow the services](/docs/configuration/#categories-follow-the-services)).

## The default snippet, before GTM

Consent Mode stores nothing: on every page, before GTM reads anything, something has to tell it the state. The snippet generated by `renderHeadScript(config)` does that:

- it reads the `ec_consent` cookie synchronously;
- if there is a valid, unexpired choice for the current revision, it calls `gtag('consent', 'default', …)` with the visitor's **real state**;
- otherwise it denies everything and adds `wait_for_update` (500 ms by default), so GTM waits for the choice before firing tags;
- it sets `ads_data_redaction` and `url_passthrough` when configured.

It is ES5, has no dependencies, and comes from the same function the runtime uses: no hand-copied cookie parser on your site.

```html
<head>
  <!-- 1. easy-cookie: Consent Mode default -->
  <script>/* output of renderHeadScript(config), or head.js / embed.js from the server */</script>

  <!-- 2. Google Tag Manager -->
  <script>(function(w,d,s,l,i){w[l]=w[l]||[];w[l].push({'gtm.start':
  new Date().getTime(),event:'gtm.js'});var f=d.getElementsByTagName(s)[0],
  j=d.createElement(s),dl=l!='dataLayer'?'&l='+l:'';j.async=true;j.src=
  'https://www.googletagmanager.com/gtm.js?id='+i+dl;f.parentNode.insertBefore(j,f);
  })(window,document,'script','dataLayer','GTM-XXXX');</script>
</head>
```

Where to get it:

| Installation | Snippet |
|---|---|
| Consent server | Already inside `embed.js`. If you load the runtime another way, use `/v1/sites/pk_…/head.js`. |
| Next.js | `<EasyCookieHead config={config} />` in `<head>`, before the GTM component (or `<EasyCookieHeadRemote>` for a console-managed config). |
| Other server-side rendering | `renderHeadScript(config)` from `@easy-cookie/core/shared`, in an inline `<script>`. |

Order matters. If GTM runs before the snippet, tags see "no consent declared" and behave as if Consent Mode were not there.

## After every choice

On the first choice and on every change, the runtime:

1. calls `gtag('consent', 'update', …)` with the new signals;
2. pushes this event to the `dataLayer`:

```js
{
  event: 'easy_cookie_update',
  easyCookie: {
    categories: { necessary: true, measurement: true, marketing: false },
    method: 'custom',          // accept_all | reject_all | custom | close
    first: true,               // first choice for this revision
    revision: '2026-11-13',
  },
}
```

A page load with a stored choice **never** pushes the event: the snippet has already set the right default, so tags never fire twice.

### Changing the event name

The event name is `googleConsentMode.eventName`, `easy_cookie_update` by default. When you migrate from another banner, set it to the event your GTM triggers already listen to, and nothing changes in the container:

```ts
googleConsentMode: { enabled: true, eventName: 'cookie_consent_update' },
```

The payload shape stays the same: categories are always under `easyCookie.categories.<id>`. If a GTM Data Layer Variable used to read other keys (say `analytics` or `marketing` at the top level), point it to `easyCookie.categories.analytics` or `easyCookie.categories.marketing`. Keeping your old category ids, as shown above, means only the variable path changes.

## Setting up Tag Manager

### The problem: tags blocked on gtm.init never fire again

In GTM, base tags (GA4 configuration, Google Ads, the Meta pixel) usually use the **Initialization** or **All Pages** trigger. With Consent Mode, a tag that requires `analytics_storage` is **held back** if consent is denied at that moment.

The catch is that GTM evaluates that trigger only once, on page load. When the visitor accepts a few seconds later, the `consent update` changes the state but does **not** replay the events that already happened. The tag stays idle until the next page, and the first pageview (the one with the traffic source, the UTM parameters, the gclid) is lost.

### The fix: a custom event trigger

1. In GTM, go to **Triggers → New → Custom Event**.
2. Event name: `easy_cookie_update` (or your `eventName`).
3. This trigger fires on: **Some Custom Events**, with the condition for the category. First create a **Data Layer Variable** named `easyCookie.categories.measurement` (and one for `marketing`), then use the condition `easyCookie.categories.measurement` equals `true`.
4. Add this trigger to the base tags **next to** the page-load trigger, not instead of it.
5. In those tags' **Advanced Settings**, set the firing option to **Once per page**. If the visitor changes another category on the same page, the event arrives again with `measurement = true` and the tag must not fire again.

| Tag | Triggers |
|---|---|
| Google tag (GA4) | Initialization · `easy_cookie_update` with `measurement = true` |
| Google Ads, Conversion Linker | Initialization · `easy_cookie_update` with `marketing = true` |
| Meta pixel (template with Consent Mode support) | All Pages · `easy_cookie_update` with `marketing = true` |

In each tag's consent settings, keep **Require additional consent** on the right signals (`analytics_storage` for GA4, `ad_storage` for Ads and Meta). The tag then fires exactly once: on load if consent was already there, or on the event when the visitor accepts.

> For third-party tags without Consent Mode support, the tag's consent setting is not enough: always use the condition on the Data Layer Variable, otherwise the `easy_cookie_update` event that follows a rejection would fire them.

### Checking with Preview

Open Tag Assistant's preview in a private window:

- on the first event (`Consent Initialization`), the **Consent** tab must show every signal as `denied`;
- after **Accept all**, the `easy_cookie_update` event appears and the base tags show as **fired** on that event;
- after a reload, the default state is already `granted` and the event does not appear.

## Basic or advanced Consent Mode

In **basic** mode, Google's tags do not load at all without consent. In **advanced** mode they load and send cookieless pings, which Google uses for modelling.

easy-cookie provides the signals in both cases: the choice depends on how you configure the tags in GTM. Advanced mode still sends data to Google before consent (without cookies): check with your adviser whether that fits your privacy notice and the guidance of your data protection authority.

## Regions

To apply the defaults to some countries only, for example when the site also has non-EU traffic:

```ts
googleConsentMode: {
  enabled: true,
  region: ['IT', 'FR', 'DE', 'ES' /* … EEA list */],
},
```

The banner, on the other hand, is shown to everyone: easy-cookie does no geolocation.
