```ts
import EasyCookie from '@easy-cookie/core';   // with a bundler
window.EasyCookie                            // with the IIFE build or embed.js
```

There is one engine per page: a single instance, and `run()` is called once.

## Starting

### `run(config)`

```ts
run(config: EasyCookieConfig | { remote: { endpoint: string; siteKey: string } }): Promise<void>
```

Starts the runtime: it shows the banner when there is no valid choice, re-applies the stored one, and mounts the reopen button and the iframe placeholders. With `remote`, it downloads the config published on the consent server.

```ts
await EasyCookie.run({ remote: { endpoint: 'https://consent.example.com', siteKey: 'pk_live_xxx' } });
```

A second call is ignored, with a warning in the console.

## Reading the state

### `get()`

```ts
get(): ConsentState | null
```

The current valid choice, or `null` when the visitor has not chosen yet for this revision (or the choice has expired).

```ts
interface ConsentState {
  id: string;                         // random id, the same one as in the register
  revision: string;
  categories: string[];               // accepted, necessary included
  services: Record<string, string[]>; // accepted services per category
  method: 'accept_all' | 'reject_all' | 'custom' | 'close' | 'withdraw';
  firstAt: string;                    // ISO, first choice with this id
  updatedAt: string;                  // ISO, latest choice
  language?: string;
}
```

### `isGranted(category)` and `isServiceGranted(service)`

```ts
isGranted(category: string): boolean
isServiceGranted(service: string): boolean
```

Both return `false` until there is a choice.

### `getConfig()`, `getLanguage()`

The resolved config (with every default filled in) after `run()`, and the language currently shown.

## Acting

| Method | Effect |
|---|---|
| `showBanner()` | Shows the first layer again. |
| `openPreferences()` | Opens the preferences panel. Use it for a "Cookie preferences" link in the footer. |
| `acceptAll()` | Accepts every category. Recorded as `accept_all`. |
| `rejectAll()` | Necessary categories only. Recorded as `reject_all`. |
| `accept(categories, services?)` | Adds these categories (and, optionally, services) to the ones already accepted. |
| `reset()` | Forgets the choice, records a withdrawal (`withdraw`) and deletes the cookie. To show the banner again, call `run()` again or reload the page. |
| `setLanguage(lang)` | Switches the language of the texts, among those in `language.available`. |
| `identify(subjectId)` | Links the anonymous `consentId` to a user id on the consent server. See below. |

Call `acceptAll()`, `rejectAll()` and `accept()` only in response to an explicit action of the visitor: consent is never inferred.

### `identify(subjectId)`

```ts
identify(subjectId: string): Promise<boolean>
```

Call it after login to link the visitor's anonymous consent id to your user id, so you can later answer access and erasure requests per user (see [Consent register](/docs/consent-register/)).

- It resolves `true` once the server has confirmed the link.
- Called **before the visitor's first choice**, it resolves `false` and remembers the id: the link is made right after the visitor chooses.
- Without a `log` block in the config there is no server to link to, and it resolves `false`.
- The runtime waits for the consent record to reach the server before sending the link, so the two never arrive out of order.

```ts
const linked = await EasyCookie.identify(user.id);
```

### Opening the preferences without JavaScript

Any element with the `data-ec-open-preferences` attribute opens the preferences panel when clicked (its default action is prevented):

```html
<a href="#" data-ec-open-preferences>Cookie preferences</a>
```

The listener is delegated on `document`, so elements added after `run()` work too, for example the `{{preferences-link}}` of a [legal document](/docs/legal-documents/). The engine's own `data-cc="show-preferencesModal"` attribute still works as well.

## Events

### `on(event, callback)`

```ts
on(event: 'ready' | 'consent' | 'change' | 'replay', cb: (detail: ConsentEventDetail | null) => void): () => void
```

Returns a function that unsubscribes.

| Event | When | `detail` |
|---|---|---|
| `ready` | Once, when `run()` has finished. | `null` |
| `consent` | The visitor's first choice for this revision. | `{ consent, changed: [], first: true }` |
| `change` | Every later change, a withdrawal included. | `{ consent, changed: ['marketing'], first: false }` |
| `replay` | On every page load with a stored choice. | `{ consent, changed: [], first: false }` |

```ts
const off = EasyCookie.on('change', ({ consent, changed }) => {
  if (changed.includes('marketing') && !consent.categories.includes('marketing')) stopPixel();
});
```

The same events are dispatched on `window` as `CustomEvent`s: `easycookie:ready`, `easycookie:consent`, `easycookie:change`, `easycookie:replay`.

```js
window.addEventListener('easycookie:consent', (e) => console.log(e.detail.consent));
```

### `onGranted(category, callback)`

```ts
onGranted(category: string, cb: () => void): () => void
```

Calls `cb` immediately when the category is already granted, otherwise the first time it becomes granted (once only). It is the simplest way to load a script from code.

## DOM-free functions

From `@easy-cookie/core/shared`, usable on the server, at build time or in middleware:

| Function | Use |
|---|---|
| `defineConfig(config)` | Type checking only, no runtime effect. |
| `validateConfig(config)` | The list of issues, `[]` when the config is valid. |
| `resolveConfig(config)` | The config with every default filled in. |
| `renderHeadScript(config)` | The Consent Mode snippet to put in `<head>`. |
| `consentFromCookieHeader(header, { revision })` | Reads the choice from a `Cookie` header. `null` when missing, expired or from another revision. |
| `parseConsent(value, { revision, expiryDays })` | The same, from the cookie value. |

Don't read `ec_consent` by hand: its format follows the engine's and may change.

```ts
import { consentFromCookieHeader } from '@easy-cookie/core/shared';

const consent = consentFromCookieHeader(request.headers.get('cookie'), { revision: config.revision });
if (consent?.categories.includes('measurement')) sendServerSideAnalytics();
```

## Next.js on the server

`@easy-cookie/next/server` has no React, so it works in Server Components, route handlers, server actions and middleware (Edge included).

| Function | Returns |
|---|---|
| `getServerConsent(source, config)` | `ConsentState \| null` |
| `isGrantedOnServer(source, config, category)` | `boolean`. Read-only categories are always granted. |
| `isServiceGrantedOnServer(source, config, service)` | `boolean` |
| `getRemoteConfig({ endpoint, siteKey, revalidate? })` | The config published on the consent server |
| `getLegalDocument({ endpoint, siteKey, kind, lang?, revalidate? })` | A published legal document, or `null`. See [Legal documents](/docs/legal-documents/). |

`source` can be the awaited `cookies()` store, `await headers()`, `request.headers`, a `Request` / `NextRequest`, or a raw `Cookie` header string. In Next 15 and later `cookies()` is async: pass the awaited value.

```ts
import { cookies } from 'next/headers';
import { getServerConsent, isGrantedOnServer } from '@easy-cookie/next/server';
import config from '@/easy-cookie.config';

const consent = getServerConsent(await cookies(), config);
const marketing = isGrantedOnServer(await cookies(), config, 'marketing');
```

### When the config lives in the console

If you manage the config in the [console](/docs/console/) and load it with `<EasyCookieProvider remote>`, there is no config file in your code to pass to these functions. `getRemoteConfig()` fetches the published one, cached by Next for 60 seconds by default (`revalidate`, `false` to cache indefinitely). It throws when nothing is published or the server is unreachable: when you gate tracking, treat a failure as "no consent".

The typical use is gating server-side GA4 events sent through the Measurement Protocol, which never pass through the browser and so ignore the banner unless you check consent yourself:

```ts
// app/api/checkout/complete/route.ts
import { cookies } from 'next/headers';
import { getRemoteConfig, getServerConsent } from '@easy-cookie/next/server';

const endpoint = process.env.CONSENT_ENDPOINT!;
const siteKey = process.env.CONSENT_SITE_KEY!;

export async function POST(req: Request) {
  const order = await completeOrder(req);

  let measurement = false;
  try {
    const config = await getRemoteConfig({ endpoint, siteKey });
    measurement = !!getServerConsent(await cookies(), config)?.categories.includes('measurement');
  } catch {
    // config unavailable: treat as no consent
  }

  if (measurement) {
    await sendGa4MeasurementProtocol({ clientId: readGaClientId(await cookies()), events: [{ name: 'purchase', params: { /* … */ } }] });
  }
  // Without consent, send nothing. Don't "anonymise" and send anyway: a Measurement Protocol hit carries a client id.
  return Response.json({ ok: true });
}
```

Rules of thumb:

- Read consent **at request time**, in the handler that has the visitor's cookies.
- For events fired later from webhooks or queues, store the boolean (and `consent.id`) with the order or other domain object at request time, and check that stored value.
- The GA client id comes from the `_ga` cookie, which only exists after consent. When it is missing, skip the event.

## React

`useConsent()` from `@easy-cookie/react` exposes the same things and re-renders the component on `consent`, `change` and `replay`:

```tsx
const { consent, ready, isGranted, isServiceGranted, openPreferences, acceptAll, rejectAll, accept } = useConsent();
```

`useEasyCookie()` gives access to the instance (`api`), the config and the language. Components: `ConsentGate`, `ConsentScript`, `ConsentEmbed`, `PreferencesLink`.
