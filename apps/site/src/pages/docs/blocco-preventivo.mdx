Il blocco preventivo è il primo obbligo: nessun cookie o tracciante non tecnico prima del consenso (art. 122 del Codice Privacy, art. 5.3 della direttiva ePrivacy). easy-cookie non indovina cosa bloccare. Lo dichiari tu nel markup, tag per tag, e il runtime lo attiva quando la categoria (o il singolo servizio) viene accettata.

## Script

Un `<script>` con `type="text/plain"` non viene eseguito dal browser. Aggiungi `data-category` con l'id della categoria e, per gli script esterni, sposta `src` in `data-src`:

```html
<!-- Script esterno: parte solo dopo il consenso a "measurement" -->
<script type="text/plain" data-category="measurement" data-service="ga4"
        data-src="https://www.googletagmanager.com/gtag/js?id=G-XXXX"></script>

<!-- Script inline: stesso meccanismo -->
<script type="text/plain" data-category="measurement" data-service="ga4">
  window.dataLayer = window.dataLayer || [];
  function gtag(){ dataLayer.push(arguments); }
  gtag('js', new Date());
  gtag('config', 'G-XXXX');
</script>
```

Quando il visitatore accetta, il runtime crea un nuovo `<script>` con gli stessi attributi, il tipo originale e la `src` reale. Gli script esterni vengono caricati in sequenza, nell'ordine del documento, così uno script inline che dipende da una libreria esterna trova la libreria già caricata.

| Attributo | Uso |
|---|---|
| `type="text/plain"` | Obbligatorio. Impedisce l'esecuzione. |
| `data-category="id"` | Categoria da cui dipende lo script. |
| `data-service="id"` | Facoltativo. Lo script parte quando è accettato quel servizio, anche se il visitatore non ha accettato tutta la categoria. |
| `data-src="…"` | Indirizzo dello script esterno. |
| `data-type="module"` | Il tipo da usare quando lo script viene riattivato (per esempio un modulo ES). |
| `data-category="!id"` | Il contrario: lo script parte quando la categoria viene **rifiutata o revocata**. Utile per attivare un'alternativa senza cookie. |

### Script già eseguiti e revoca

Uno script già eseguito non si può "scaricare". Quando il visitatore revoca una categoria:

1. i cookie dichiarati nei servizi di quella categoria vengono cancellati;
2. Consent Mode riceve l'`update` con i segnali negati;
3. la pagina si ricarica, così gli script revocati non sono più in memoria.

Il ricaricamento si può disattivare con `ui.reloadOnWithdraw: false`, se gli script coinvolti sanno fermarsi da soli (per esempio PostHog con [l'adattatore](/docs/posthog/)).

### Cookie da cancellare

La cancellazione usa i cookie dichiarati in `services.*.cookies`. Dichiarali tutti, anche quelli impostati dalla libreria del fornitore, con `pattern: true` per le famiglie di nomi:

```ts
cookies: [
  { name: '^_ga', pattern: true, duration: { it: '2 anni', en: '2 years' } },
  { name: '_gid', duration: { it: '24 ore', en: '24 hours' } },
],
```

I cookie impostati su domini di terze parti (per esempio `.youtube.com`) non si possono cancellare dal tuo sito: dichiarali con `domain` perché compaiano nella policy, sapendo che la cancellazione vale solo per quelli di prima parte.

## Iframe e contenuti incorporati

Video, mappe e post social incorporati impostano cookie appena l'iframe si carica. Lascia `src` vuoto e metti l'indirizzo in `data-src`:

```html
<iframe data-category="experience" data-service="youtube"
        data-src="https://www.youtube-nocookie.com/embed/VIDEO_ID"
        width="560" height="315" title="Video: presentazione del prodotto"></iframe>
```

Finché la categoria è spenta, l'iframe resta vuoto e nascosto, e al suo posto compare un segnaposto con le stesse proporzioni (calcolate da `width` e `height`). Il segnaposto dice quale servizio e quale categoria servono, e offre due scelte:

- **Mostra il contenuto** carica solo questo iframe, adesso, senza salvare un consenso;
- **Attiva sempre «Esperienza»** accetta l'intera categoria e registra la scelta.

Il testo del segnaposto si cambia con `texts.<lingua>.embed`, il suo aspetto con le variabili `--ec-*` (vedi [Tematizzazione](/docs/tematizzazione/)).

In React c'è il componente equivalente:

```tsx
import { ConsentEmbed } from '@easy-cookie/react';

<ConsentEmbed
  category="experience"
  service="youtube"
  src="https://www.youtube-nocookie.com/embed/VIDEO_ID"
  title="Presentazione del prodotto"
  width={560}
  height={315}
  allowFullScreen
/>
```

## Script caricati dal codice

Se carichi uno script dal tuo JavaScript invece che dal markup, aspetta il consenso con `onGranted`:

```ts
EasyCookie.onGranted('marketing', () => {
  const s = document.createElement('script');
  s.src = 'https://connect.facebook.net/en_US/fbevents.js';
  document.head.appendChild(s);
});
```

La callback parte subito se la categoria è già concessa, e altrimenti la prima volta che lo diventa. In React lo stesso lavoro lo fanno `<ConsentScript>` e `<ConsentGate>`.

## Lato server

Il blocco nel browser non copre le chiamate che il tuo server fa a terzi per conto del visitatore, come il Measurement Protocol di GA4. Leggi il consenso dalla richiesta e non inviare nulla senza:

```ts
import { consentFromCookieHeader } from '@easy-cookie/core/shared';

const consent = consentFromCookieHeader(request.headers.get('cookie'), { revision: config.revision });
if (consent?.categories.includes('measurement')) await sendServerSideAnalytics();
```

In Next.js usa `getServerConsent()` da `@easy-cookie/next/server`.

## Cosa resta a te

easy-cookie blocca solo quello che marchi. Prima di andare online:

- cerca nel codice e nei template tutti i tag di terze parti, compresi quelli aggiunti dai plugin del CMS;
- controlla i font e le librerie caricati da CDN di terzi, che possono trasmettere l'indirizzo IP;
- apri il sito in una finestra anonima e verifica nella scheda Network che, prima della scelta, non partano richieste verso terzi.
