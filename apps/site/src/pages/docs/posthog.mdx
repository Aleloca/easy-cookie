PostHog can count visits without cookies, in **cookieless** mode. The adapter uses it like this:

| Visitor state | PostHog |
|---|---|
| No choice yet | Captures nothing (default). With `beforeChoice: 'cookieless'`, counts visits without cookies, as after a rejection. |
| Rejected `measurement` | Cookieless only: no cookies, no storage, no person profiles. Autocapture, exceptions, web vitals and heatmaps are dropped. |
| Accepted `measurement` | Normal capture with cookies, then `identify()` for logged-in users. |

Switching from one state to another happens without reloading the page.

## Requirements

- `posthog-js` with `cookieless_mode` support (1.200 or later).
- **Cookieless server hash mode** enabled in the PostHog project settings. Without it, PostHog's server discards cookieless events.
- PostHog initialised with `cookieless_mode: 'on_reject'`. `posthogInitOptions()` does this for you.

```sh
pnpm add @easy-cookie/posthog posthog-js
```

## Usage

```ts
import posthog from 'posthog-js';
import EasyCookie from '@easy-cookie/core';
import { connectPostHog, posthogInitOptions } from '@easy-cookie/posthog';

posthog.init('phc_…', {
  ...posthogInitOptions({ api: EasyCookie }),
  api_host: 'https://eu.i.posthog.com',
});

const disconnect = connectPostHog(posthog, EasyCookie, {
  category: 'measurement',            // default
  identify: () => session?.user?.id,  // optional, called after opt-in only
});
```

With React, connect it in an effect inside the provider:

```tsx
'use client';
import { useEffect } from 'react';
import posthog from 'posthog-js';
import { useEasyCookie } from '@easy-cookie/react';
import { connectPostHog } from '@easy-cookie/posthog';

export function PostHogConsent({ userId }: { userId?: string }) {
  const { api } = useEasyCookie();
  useEffect(() => (api ? connectPostHog(posthog, api, { identify: () => userId }) : undefined), [api, userId]);
  return null;
}
```

Do **not** block the PostHog script with `type="text/plain"` in your markup: it has to load to count in cookieless mode. The adapter decides what it may do.

## API

### `connectPostHog(posthog, api, options)`

The adapter listens to the `ready`, `replay`, `consent` and `change` events and applies the current state immediately, in case the stored choice was replayed before you connected. It waits until the runtime has read the stored choice, so a returning visitor who accepted is never opted out by mistake.

- **Granted:** it calls `posthog.opt_in_capturing()` (skipped when already opted in), then `posthog.identify(id)` when `identify()` returns an id that differs from the current one.
- **Not granted, with a choice:** it calls `posthog.opt_out_capturing()`. With `on_reject`, PostHog keeps counting anonymously and without cookies.
- **No choice yet:** with the default `beforeChoice: 'pending'` it captures nothing, and clears an opt-in left in storage by an earlier setup. With `'cookieless'` it opts out, so PostHog counts cookieless.

Opt-in does **not** send a `$opt_in` event: easy-cookie already records the consent in its own register.

It returns a function that disconnects the adapter.

| Option | Default | Effect |
|---|---|---|
| `category` | `'measurement'` | Category that allows PostHog cookies and person profiles. |
| `service` | — | Decide on this service's consent instead of the category, for example `'posthog'`. |
| `identify` | — | Returns the logged-in user id. Called after opt-in only, so the identified profile exists only with consent. |
| `beforeChoice` | `'pending'` | `'pending'`: capture nothing until the visitor chooses. `'cookieless'`: count visits without cookies before the choice, as after a rejection. Use it only when your privacy policy covers cookieless measurement without consent. |
| `sessionReplay` | `false` | Start session recording on opt-in and stop it on opt-out. |

With `sessionReplay`, a visitor who accepts while PostHog is in cookieless mode (before the choice with `beforeChoice: 'cookieless'`, or after an earlier rejection) gets session replay started **on the same page**, without waiting for the next page load. If a different `posthog-js` version does not allow the restart, recording simply starts on the next page.

### `posthogInitOptions(options?)`

Returns the recommended init options. Spread your own options after it:

```ts
{
  cookieless_mode: 'on_reject',
  persistence: 'localStorage+cookie',   // used only after opt-in
  person_profiles: 'identified_only',
  before_send: consentBeforeSend(options),
}
```

### `consentBeforeSend({ category?, api?, isGranted?, drop? })`

A `before_send` filter. Without consent it drops `$autocapture`, `$rageclick`, `$dead_click`, `$exception`, `$web_vitals` and heatmap events (`$$heatmap`, `$heatmap`). The list is exported as `NON_ESSENTIAL_EVENTS`, and you can replace it with `drop`. Pageviews and your own events are kept.

To decide whether there is consent, it uses, in order:

1. `isGranted`, when you pass it;
2. the runtime, when you pass `api`;
3. otherwise the state published by the head snippet (`window.__easyCookieHead`), which is available before the runtime has loaded.

## In the cookie policy

Declare PostHog as a service of the `measurement` category, with its cookies, so it appears in the banner and in the policy. The [service library](/docs/service-library/) has a ready-made `posthog` entry:

```ts
import { catalogToService, findCatalogEntry } from '@easy-cookie/core/catalog';

services: {
  posthog: catalogToService(findCatalogEntry('posthog')!),
},
```

Or declare it by hand:

```ts
posthog: {
  category: 'measurement',
  label: 'PostHog',
  provider: 'PostHog Inc.',
  privacyUrl: 'https://posthog.com/privacy',
  cookies: [{ name: '^ph_.*_posthog$', pattern: true, duration: { it: '1 anno', en: '1 year' } }],
},
```

Cookieless mode uses no cookies, but it still processes browsing data. Describe it in your privacy notice, and check with whoever handles your site's privacy that the legal basis is adequate.
